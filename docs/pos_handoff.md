## 回答が POS に届くまでの流れ

1. 店舗が導入アンケート(https://pokkiri-night-survey.vercel.app)に答える
2. 最後のページで「文章をコピー」を押し、LINE で担当者に送る
3. 担当者が運営コンソールで、その文章を貼り付けて取り込む
4. 取り込んだ内容が、その店舗の設定画面に反映される

外部から叩ける送信経路(API・共有シークレット)は作らない。貼り付けでの取り込みに一本化する
(2026-09-26 のセキュリティ方針。コミット 46b35cb)。

## 導入前点検(2026-10-21。POS main f220722 を読んだ結果)

会計・税サ・値引値増・バック・フロアと管理画面の連動を、POS のコードと計算関数
(`computeBill`・`computeDayBacks`)で確かめた。計算と、試算と確定の一致は問題なし。
例(外税・税サ32%・2名・延長1回・本指名・ドリンク2杯・ボトル・個室料・値引5%)は
合計 39,666円、あやのバック 4,400円で、手計算と一致した。

- [x] **外税＋カード手数料で会計が止まる:** 外税の卓は、カード手数料(店舗共通・決済方法ごと・売掛)を0%で会計し、
      確定を止めない(2026-10-21。pokkiriofficial/nightwork-pos#614 を main にマージ済み・ADR-0017)。
      設定の率は消さない(内税に戻すとそのまま効く)。以前は、現金の会計まで確定がエラーで止まっていた
- [x] **外税の店は端数の丸めが効かない:** 自動の丸めは内税だけ(`compute.ts`)。会計画面の上書きの操作は
      2026-08 に外してあり、常に null を送る(`bill-flow.tsx:643`)。依頼者の判断(2026-10-21)で、計算は変えず、
      管理画面の説明を直した(内税の店は自動で丸め、外せない／外税の店は丸めない。端数は「値引(円)」)。
      pokkiriofficial/nightwork-pos#615 を main にマージ済み
- [ ] **商品ごとの「税サ込み(サ料なし)」が無い:** サ料は全商品に掛かる(`compute.ts:380-389`)。
      対象外はハウスチャージ・深夜割増・個室料・カード手数料だけ。税サ込みの商品がある店のために、
      商品ごとの設定を足すか決める。`products.subtotal_price_yen` のコメント
      (`src/db/schema/products.ts`)は「消費税・サービス料の基準」と書くが、実際は％バックにだけ使う
- [x] **「税サ別商品の税サ等」の中身が3通り:** 注文内容画面＝サ料＋ハウスチャージ、
      会計画面＝サ料だけ、紙の伝票＝合計−小計−調整(税・個室料を含む)だった。例では画面 5,510円・紙 12,116円。

- [ ] **バックのルールは営業日の版で計算する:** 卓にピン留めした back_rules は使わず、

- [x] **深夜割増を、小計の％でも乗せられるようにした**(2026-10-23。pokkiriofficial/nightwork-pos#641 を main にマージ済み)。
      設定 `pricing.lateNightSurcharge` に `mode`(yen=定額・既定／percent=小計の％)と `percent`(0〜100)を足した。
      ％のときは、値増と同じ基準(小計)・同じ端数(切り捨て)で、サービス料の対象に入る。バックの基礎額には入らない。税は掛かる。
      例: ベース1,000円・20%・サ料10% → 1,000+200+120 = 1,320円(定額200円なら1,300円)。明細の行は `house_charge` の再利用(migration なし)。
      既存の版は定額のまま動く。設定は管理画面「設定＞料金」とフロア「設定＞料率」で変える。フロアの金額欄の「1セットあたり」は「1会計あたり」に直した
- [x] **先に一部だけ精算する会計で、定額の深夜割増が二重に付く不具合を直した**(2026-10-24。pokkiriofficial/nightwork-pos#650 を main にマージ済み)。
      コードの上の疑いを、テストで確かめた: 割増2,000円・小計12,000円の卓で、先に精算する6,000円の会計が8,000円になり、
      卓を閉じる会計にも2,000円が乗って、合計16,000円(正しくは14,000円)になっていた。定額は、個室料・延長・指名料と同じく、
      卓を閉じる会計にだけ乗せる。％は、それぞれの会計の小計に掛かるので、分けても合計が合う(二重にならない)。
      過去の会計で、二重に請求された卓があったかは、調べていない(確定済みの会計は変わらない)
- [x] **深夜割増の質問(金額か率)を本番のアンケートに出した**(2026-10-23。このリポジトリの #38。POS の取り込み #643 を先に本番へ出してから)。
      本番のアンケートで、3問の表示と、「(1セットあたり)」が消えていることを確認した
- [x] **アンケートの答え → 取り込み → 設定 → 卓を開く → 会計、の通しのテスト**を足した(#650。`tests/late-night-survey-to-bill.test.ts`)。
      取り込む前の確認画面と、反映後の読み戻しも、深夜割増(定額／小計の％)を読める言葉で出す
- [ ] **ハウスチャージ(人数分にしない設定)が、先に一部だけ精算する会計にも付く:** 6,000円の会計が7,000円になることを、
      テストで確かめた(2026-10-24)。同じ理由で、卓を閉じる会計と二重になる可能性がある。深夜割増と違って、店の運用の考え方次第なので、

## 名簿・キャスト別バックについて(2026-10-07 追加)

名簿(テーマ5)とキャスト別バック(テーマ7)は、貼り付け取り込みの対象外。導入担当が POS の画面に入れる。

- [x] **POSに列を作る(2026-10-07 作成を承認済み):** 読み仮名(キャスト・スタッフ)、入店日(キャスト・スタッフ)。
      cast_profiles・staff_profiles に列を足し、基本情報カードに入力欄を出す。migration を作るのは沢田さん。
      本番DBへの適用が先、コードはあと(POSのCLAUDE.md 6・8)。それまでは、担当者のメモとして扱う
- [x] **区分の対応:** 在籍=status:active、体験入店=status:trial、派遣=isDispatch、日払い=isDailyWage。
      体験入店と派遣は、POSでも同時に選べない
- [ ] **キャスト別バック:** メンバー台帳の「バック(個人ごと)」に入れる(店舗がやる)。対象は
      セット・延長・指名・担当卓の売上・ドリンク・ボトル・フードの7種類。個人ごとに切り替えると、
      同じ種類の店舗共通ルールは止まる。①で「キャストごとに違う」と答えた種類だけが対象

## 回答の文章の書式

```
【ポッキリ.Night初期セットアップフォーム】
回答日:2026年9月28日(月)
訪問日:10月5日(月)        ← URL に ?visit= があるときだけ

■店舗名
クラブ〇〇

■料金セット
セット1/60/8000、VIPセット/60/15000
```

- 1問ごとに、空行・「■質問名」・答え の順に並ぶ。出ていない質問(条件に合わない質問)と説明だけの欄は書かれない
- 選択肢は、その文字のまま。複数選べる質問は「、」でつなぐ
- 「未定」は、まだ決まっていないという答え
- 「その他」「あり」「記入」に書き添えた値は、後ろに「(値 単位)」で付く。例:`あり(10%)`
- 選んだ選択肢の横に入力した値も、同じ形で付く。例:サービス料 `率で指定(20%)`・`金額で指定(1000円)`
- 数字の質問で単位があるものは「値 単位」。例:`50000 円`
- 金額・率は「値単位」。例:`50%` `1000円`
- 時刻は `HH:MM`
- ダイヤル(`dial`)で選ぶ質問は、選んだ文字のまま。例:遅刻控除の時間の区切り `15分`
- 表は、1行を「/」でつなぎ、行どうしを「、」でつなぐ。空のマスは `-`
- 表の列のうち、条件に合わず出していない列は、文章にも入らない(例:個室料の有無が「なし」なら、卓の一覧は「卓名/席数」だけ)
