## ■重要論点

1. **「オーナーのみ」はサーバー側で強制する。** 画面で隠すだけでは不十分。API・Server Action の入口で `owner` を確認し、`manager` / `staff` は拒否する。テストで「店長は 403 相当」を固定する
2. **補正の持ち方(推奨)**: 元の会計記録は書き換えず、**補正値を別に持つ**。表示は「実績 / 補正 / 合計」を出せる形にする。理由は、あとで実績と食い違いを説明できることと、元に戻せること
3. **変更の記録を残す(推奨)**: 誰が・いつ・どの経路を・何人から何人にしたか。オーナー1人の店でも、後日の説明に必要
4. **デモ用オーナー設定の確認(最優先の安全確認)**: `PUBLIC_DEMO_TENANT_ID` / `PUBLIC_DEMO_OWNER_USER_ID` が本番に設定されていると、**未ログインの誰でもそのテナントのオーナーとして書き込める**(`src/features/auth/session.ts:82-83`)。設定されていれば「オーナーのみ」が成立しない。確認は Vercel の環境変数の**名前だけ**を見る(値は見ない・出力しない)。設定されていたら実装より先にユーザーへ報告する
5. **集計の全表示に反映する。** 補正を一部の画面にしか効かせないと、画面ごとに人数が違って見える

## ■示唆

- 最大のリスクは「画面ではオーナーだけに見えるが、API は誰でも叩ける」状態。ここが依頼の核心
- A案は「集計値の補正」なので、元データの会計記録は触らない設計が安全。ただし**保存形が未確認**なので、確認(未確認 1・2)の結果で設計を確定する
- 影響範囲(未確認 2・5)が大きい場合は、実装前にユーザーへ「補正を効かせる画面の一覧」を示して合意を取る
